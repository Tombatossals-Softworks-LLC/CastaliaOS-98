#About CastaliaOS

Remember beveled buttons, a Start menu, glossy title bars, and a file explorer with a friendly blue task pane? CastaliaOS recreates that feeling as a brand‑new, legally‑clean system you can actually run on period hardware.

CastaliaOS 98 PE ("Powerful Edition") is a from‑scratch desktop operating system that captures the look and feel of late‑90s / early‑2000s computing while being completely original. Hand‑written in portable C, it boots on a 386, composites its entire UI with an original software renderer, and ships a real desktop shell: a Start‑style launcher, a Windows XP‑style file explorer, four virtual desktops, window snapping, and a themeable toolkit — with 20+ apps on top, including a Winamp‑style WAV player, a benchmark suite, and Klondike Solitaire.

It is free and open source under the MIT license, and it develops and unit‑tests on a modern "host" build so the whole stack stays verifiable — while shipping to real DOS via Open Watcom.

What makes it notable

  • 100% original code and artwork — a real, runnable retro OS, not a theme or a mod.
  • Runs on genuine DOS hardware, yet develops and tests on a modern host build.
  • An original software renderer with XP‑style glossy chrome, drop shadows, and dirty‑rect compositing in a tiny memory budget.
  • Extensible: discoverable .CAPP add‑ons appear as first‑class launcher apps — something Windows 98 SE never had.
  • Four virtual desktops, window snapping/tiling with a live preview outline, right‑click menus, and live theming.

#Technical

A small, layered design in portable C. Nothing above the platform layer touches the hardware — which is what lets the same stack build on DOS and on a host.

The stack we used

  • C (strict C89) for the portable core; Watcom‑compatible
  • Open Watcom for the DOS target (DOS/4GW, 32‑bit protected mode)
  • Any C89 compiler for the headless host build (CI + screenshots)
  • Small Python helpers author fonts/icons offline
  • Zero runtime dependencies; bundled Spleen font (BSD), optional Tango icons

The rendering model

The whole UI composites into one 32‑bit XRGB back buffer in system RAM. Only present() converts the dirty rectangles to real hardware — a search‑free 3‑3‑2 palette at 8bpp or RGB565 at 16bpp. No per‑pixel alpha: a 1‑bit magenta color key for icons/cursors and cheap edge‑strip shadows keep XP‑style chrome inside a period memory budget.

Verified by 1,211 host unit‑test checks, nine end‑to‑end scenes, a strict‑C89 (Watcom) lint over every portable source, and a golden‑screenshot pipeline.

Six layers: Platform → System → Graphics → Window Manager → UI → Shell → Apps. Extensible via a documented .CAPP add‑on ABI.

#Roadmap

Now — v0.1.0

  • Bootable, themeable desktop
  • WM, UI toolkit, virtual desktops, snapping
  • 20+ apps, incl. XP file manager & media player
  • 457 tests + golden screenshots

Next — Phase 2–3

  • Drag‑and‑drop in the file manager
  • Real Sound Blaster DAC audio streaming
  • ARP/IP/UDP/TCP over the packet‑driver seam
  • Downloadable theme & icon packs

Later — Phase 4+

  • Friendly installer + bootable CD/USB image
  • A catalog for .CAPP add‑ons
  • A small third‑party SDK
  • Localization & low‑end tuning

The dream: an original desktop a community can extend — where a .CAPP you wrote on a modern laptop drops onto a 386 and just runs, and the whole thing still fits on a couple of floppies.
